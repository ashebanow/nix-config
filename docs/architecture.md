# Lumquat NixOS Configuration Architecture

This document describes the architectural decisions and patterns for the lumquat AI server configuration.

## Core Architecture Decisions

| Decision | Choice |
|----------|--------|
| Pattern | Full dendritic pattern (flake-parts + import-tree) |
| NixOS Modules | Pure flake-parts modules (works for NixOS + HM) |
| Deployment | Colmena (prepared for multi-server) |
| Remote Building | Deferred until needed |
| Container Runtime | Podman with Quadlets |
| LLM Containers | Separate containers per model (from Strix Halo toolboxes) |
| GPU | AMD RDNA 3.5 with GPU passthrough |
| Monitoring | Cockpit web UI |
| Remote Access | Tailscale (LLMs routed through Aperture only) |
| Secrets | sops-nix (inline, no separate repo) |
| Extensibility | Designed for future servers |

---

## Dendritic Pattern Overview

The dendritic pattern organizes Nix configurations by **feature**, not by configuration class.

### Traditional NixOS Layout
```
nixos/
  lumquat/
    configuration.nix
home/
  lumquat/
    home.nix
```
Problem: Cross-cutting features split across directories, `specialArgs` chains.

### Dendritic Layout
```
modules/
  nixos-base.nix      # Timezone, base packages (all NixOS hosts)
  llm-serve.nix       # LLM serving feature (applies to NixOS only)
  tailscale.nix       # Tailscale feature (applies to NixOS only)
  cockpit.nix         # Cockpit feature (applies to NixOS only)
hosts/
  lumquat/
    configuration.nix  # Host composition (imports features)
    hardware-configuration.nix  # Host-specific hardware (generated by nixos-generate-config)
```
Benefit: One file = one feature across all applicable config classes.

> **Note**: `hardware-configuration.nix` is host-specific (file systems, boot, kernel params)
> and generated by `nixos-generate-config`. It lives in the host directory alongside the
> composition module, not in the shared features directory.

## Module Pattern: deferredModule Containers

The core dendritic mechanism is the `deferredModule` type in flake-parts. From `modules/infra/module-containers.nix`:

```nix
{lib, ...}: {
  options.my.modules = {
    nixos = lib.mkOption {
      type = lib.types.lazyAttrsOf lib.types.deferredModule;
      default = {};
      description = "NixOS module fragments keyed by feature name";
    };
    home-manager = lib.mkOption {
      type = lib.types.lazyAttrsOf lib.types.deferredModule;
      default = {};
      description = "Home Manager module fragments keyed by feature name";
    };
  };
}
```

### Feature Module Structure

Each feature module exports deferred modules:

```nix
# modules/features/llm-serve.nix
_: {
  my.modules.nixos.llm-serve = {config, pkgs, ...}: {
    # This module fragment will be composed into NixOS configurations
    virtualisation.podman = {
      enable = true;
      # ... podman config for LLM containers
    };
  };
}
```

### Host Composition

Hosts import feature modules via the deferredModule system:

```nix
# modules/hosts/lumquat.nix
{inputs, ...}: {
  configurations.nixos.lumquat = {
    system = "x86_64-linux";
    modules = [
      # Infrastructure modules
      inputs.self.nixosModules.lumquat-infra
      # Feature modules
      inputs.self.nixosModules.nixos-base
      inputs.self.nixosModules.podman-base
      inputs.self.nixosModules.llm-serve
      inputs.self.nixosModules.tailscale
      inputs.self.nixosModules.cockpit
      inputs.self.nixosModules.sops-nix
      # Host-specific hardware
      ./hardware-configuration.nix
    ];
  };
}
```

## Podman + Quadlets Configuration

### Base Podman Setup

From Fred Drake's `podman-server.nix` and Mango's config:

```nix
# modules/features/podman-base.nix
_: {
  my.modules.nixos.podman-base = _: {
    environment.systemPackages = with pkgs; [
      podman-tui
      dive  # Image layer inspection
    ];

    virtualisation = {
      containers.enable = true;
      podman = {
        enable = true;
        dockerCompat = true;  # docker CLI compatibility
        defaultNetwork.settings.dns_enabled = true;
      };
    };
  };
}
```

### Quadlet Configuration for LLM Containers

Quadlets are systemd unit files for containers. In NixOS, use `virtualisation.podman.containers`:

```nix
# modules/features/llm-serve.nix
_: {
  my.modules.nixos.llm-serve = {config, pkgs, ...}: {
    virtualisation.podman = {
      containers = {
        # Qwen-27B for coding
        qwen-27b = {
          image = "ghcr.io/ggerganov/llama.cpp:server";
          autoStart = true;
          environment = {
            MODEL = "/models/qwen-27b-q4_k_m.gguf";
            HOST = "0.0.0.0";
            PORT = "8080";
          };
          volumes = [
            "/var/lib/llm-models:/models:ro"
          ];
          # GPU passthrough for AMD RDNA 3.5
          devices = ["/dev/dri"];
          environmentFile = ["/run/secrets/llm-serve-env"];
        };

        # DeepSeek v4 for planning/multimodal
        deepseek-v4 = {
          image = "ghcr.io/ggerganov/llama.cpp:server";
          autoStart = true;
          environment = {
            MODEL = "/models/deepseek-v4-q4_k_m.gguf";
            HOST = "0.0.0.0";
            PORT = "8081";
          };
          volumes = [
            "/var/lib/llm-models:/models:ro"
          ];
          devices = ["/dev/dri"];
          environmentFile = ["/run/secrets/llm-serve-env"];
        };
      };
    };
  };
}
```

### GPU Passthrough for Strix Halo

The Strix Halo APU requires specific kernel parameters (already set in hardware-configuration.nix):
- `amd_iommu=off` — required for stability
- `amdgpu.gttsize=126976` — expose ~124 GB VRAM
- `ttm.pages_limit=32505856` — full TTM pool

Container needs `/dev/dri` device access for GPU.

## Tailscale + Aperture Configuration

### Tailscale Setup

```nix
# modules/features/tailscale.nix
_: {
  my.modules.nixos.tailscale = {config, ...}: {
    services.tailscale = {
      enable = true;
      useRoutingFeatures = "server";  # Act as exit node capable
      authKeyFile = "/run/secrets/tailscale-auth-key";
    };

    # Open firewall for Tailscale
    networking.firewall.checkReversePath = "loose";
    networking.firewall.trustedInterfaces = ["tailscale0"];
  };
}
```

### LLM Access via Tailscale (No Direct Access)

The requirement: LLMs visible **only** through Tailscale Aperture, not directly exposed.

This means:
1. LLM containers bind to `127.0.0.1` or `tailscale0` only
2. Tailscale serves as the reverse proxy/API gateway
3. Cockpit can be accessed via Tailscale SSH (no separate web exposure)

**Note**: Tailscale Aperture integration needs further investigation:
- Does Aperture support custom upstream backends (llama.cpp servers)?
- Will need to configure Tailscale as API gateway in front of local LLM containers

## Cockpit Configuration

```nix
# modules/features/cockpit.nix
_: {
  my.modules.nixos.cockpit = _: {
    services.cockpit = {
      enable = true;
      port = 9090;
      # Optional: restrict to Tailscale
      # listenAddresses = [{ addr = "127.0.0.1"; port = 9090; }];
    };

    networking.firewall.allowedTCPPorts = [ 9090 ];

    environment.systemPackages = with pkgs; [
      cockpit-podman  # Podman UI in Cockpit
    ];
  };
}
```

### Access Control
- Cockpit port 9090 can be restricted to localhost or Tailscale interface
- Podman containers visible through Cockpit's podman plugin

### Secrets Directory Structure

```
secrets/
├── keys/
│   └── lumquat.age           # Age key for lumquat host
└── secrets.nix               # Secret file definitions

### secrets.nix Example

```nix
# secrets/secrets.nix
{
  # Tailscale auth key
  "tailscale-auth-key" = {
    owner = "root";
    group = "tailscale";
    mode = "0640";
  };

  # LLM serving environment
  "llm-serve-env" = {
    owner = "root";
    mode = "0600";
  };

  # Additional secrets...
}
```

### Feature Module with SOPS

```nix
# modules/features/sops-nix.nix
_: {
  my.modules.nixos.sops-nix = _: {
    imports = [sops-nix.nixosModules.sops];

    sops = {
      defaultSopsFile = ../secrets/secrets.yaml;
      age.keyFile = /etc/nix/secrets/lumquat.age;
      age.generateKey = true;  # Or use existing key
    };

    # Secrets are available at /run/secrets/<name>
  };
}
